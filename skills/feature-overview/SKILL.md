# Feature Overview

Write feature overviews that are simple, clear, and direct.

## Use when

- The team needs a quick feature summary.
- You need to register how a feature works.
- You need a visual overview (PDF/image/slide style).

## Default structure

Use this order unless the user asks for another format:

1. Feature summary
2. Problem solved
3. Scope
4. How it works
5. Technical notes
6. Impact
7. Risks, limitations, and trade-offs
8. Next steps

## Writing style

- Short sentences.
- Clear section titles.
- Bullet points over long paragraphs.
- No vague claims.

## Visual output rule

If the output is visual:

1. Always include `assets/logo.svg`.
2. Keep layout clean and readable.
3. Make title and key points obvious.

## Final check

Before finalizing, verify:

- It is clear for someone new.
- It covers behavior, impact, and constraints.
- It is concise.
- Visual outputs include `assets/logo.svg`.
